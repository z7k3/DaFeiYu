## 五、已知限制（诚实清单）

1. **文字发送会让微信激活自己**（客户端行为）。已用"窗口挪到屏幕外"规避视觉打扰；代价是她的微信窗口在屏幕外看不见。
2. **不切会话才能完全无感**：切会话本身会激活窗口，虽然瞬间还原，但屏幕外方案已覆盖。
3. **表情包/语音必然切前台**：发图/录音都需要真实焦点，无法后台化。
4. **完全后台发图做不到**：`WM_PASTE` 能送达但微信不接受媒体（实测输入框仍为空）。
5. **相关性过滤器仍会整批误杀**：查询里带时间词/疑问残留时（"今晚南昌天气"→锚点"今晚南昌"），会把 10~30 条全拒。目前靠查询改写缓解，未做覆盖率阈值改造。
6. **中国天气网只到区县级（9 位代码）**；少数新区（红谷滩）只有乡镇代码，会退回上级城市并标注。
7. **启动器音色下拉只拉第一页 100 条**（库共 15572），且"搜索其他音色"是本地过滤；要用手动填 ID（需重编 EXE 才能彻底修）。
8. **启动器保存是整份文件覆盖**：手改 `data/voice-send.json` 前先在界面刷新，否则保存会覆盖掉手改内容。
9. **日志已脱敏**：不再记录聊天正文/昵称/wxid，排查只能靠长度、哈希、原因码。

## 七、运维手册

### 改完代码怎么生效

| 改动位置 | 生效方式 |
|---|---|
| `src/`（内核） | 启动器点「重启内核」 |
| `bridge/`（Python 桥接） | 启动器点「重启桥接」 |
| 启动器 `launcher/` | 需重编 EXE：`dotnet publish launcher/WhaleLauncher.csproj -c Release -o launcher/publish -p:PublishSingleFile=true -p:SelfContained=false` 再复制到根目录（**本机没有 .NET SDK，改不了启动器**） |
| `config.json` | 热重载（启动器保存即时生效） |
| `data/voice-send.json` | 每次语音合成都重读，保存即生效 |

### 日志与诊断

- 内核日志：`WhaleGirl\data\kernel.log`（10MB 轮转）
- 桥接日志：`WhaleGirl\data\bridge.log`，启动器「微信桥接」页可直接看
- 关键埋点：`[fgtrace]`（前台变化，仅诊断期保留）、`[addr-shadow] diverge`（判定分歧）、`[delivery] stage=...`（投递结果）、`[voice]`、`[sticker]`、`[search] stage=...`
- 诊断命令：`python -m bridge --bg-probe`（只读自检）、`node server.js --doctor`（环境自检）

### 常见问题速查

| 现象 | 先看什么 |
|---|---|
| 她不回消息 | `kernel.log` 有无 `result=skip reason=...`；`bridge.log` 有无 `input_not_empty`/`发送最终失败` |
| 回了但你收不到 | `bridge.log` 搜 `[delivery]`：`send_failed` → 输入框/通道问题；`voice_confirmed` → 语音通道 |
| 窗口闪/抢前台 | 确认 `noFlash` 是否 true；`[fgtrace]` 看是哪一步（切会话 or 打字） |
| 搜索质量差 | `[search] stage=route_failed`（路由超时）、`relevant:0`（相关性误杀）、`sources=`（来源） |
| 语音没声音 | `自动语音：xxx` 行；`VB-Cable` 设备状态；`voice-send.json` 的 Device |

## 十、给接手者的提醒

1. **先读 `AGENTS.md`**（仓库根目录）：零 npm 依赖、中文注释讲"为什么"、日志不打正文、`vendor/runtime` 只读、改完要配测试。
2. **微信是客户端，不是我们的进程**：任何"改微信行为"的想法都要先做实验验证（本次多次因为假设错误返工）。
3. **改判定/阈值类逻辑，先做影子对比再切**：标量启发式一定会出现"调松乱插嘴、调紧漏接"。
4. **实验必须用干净基线**：本次两次误判都是因为"测的时候微信已经在前台"，结论不可靠。做前台相关实验要先 `SetForegroundWindow` 到非微信窗口。
5. **改动前先 `git status`**：仓库是唯一可信源；运行目录随时可能被官方更新覆盖。
