# 提示词与人设设置

## 启动器入口

人设页按「人设与预设、身份关系、表达偏好、上下文与记忆」单列分区滚动，不放顶部跳转小标签。外观经历、补充提示词和清空记忆按需展开。

维护与实现开关在「设置 → 高级模式 → 对话与维护」，不再在人设页重复显示；链接与联网在设置页，插件、表情包、朋友圈和主动发送各在专页。移动入口不删除已有配置或 API。

## 三层各管什么

- **基础人设**：名字、年龄、职业、外观、性格、背景，决定角色是谁与内在性格。
- **自定义提示词**：补充基础人设的细节；与基础字段冲突时，明确填写的当前基础字段优先。旧预设需要核对基础字段；内置只读预设先复制，安装的人设可直接编辑。
- **顶嘴人格**：对已认证主人持续采用刀子嘴豆腐心的表达，不改内在感情、关系、事实与办事态度，也不强加情侣关系。

## 交流偏好

- **主动延伸话题**：开启允许自然追问或延伸，不要求每条都问。关闭只回应当前内容，必要澄清仍允许。它不负责定时或无人发消息时主动发送。
- **主动表达观点**：开启允许表达偏好和独立判断。关闭少主动发表主观立场，仍会解释事实、纠错，并在被询问时据实分析。它与顶嘴独立。
- 默认和自定义人设共用这些偏好；遇到冲突，当前交流设置优先于人设中的表达习惯。

## 长度、上下文与能力

- 私聊和群聊字数限制用于普通回复；认真讨论使用单独的讨论上限。提示词约束不保证模型逐字准确计数，发送层另有长度处理。
- 历史条数、记忆预算决定输入材料；最多分几条主要控制发送，不需要都写成重复规则。
- 颜文字用量同步到提示词，由发送层概率追加；要求模型不再自行叠加。0% 对应关闭硬闸。百分比不是全部回复的精确频率保证，模型遵循和其他发送规则仍会影响最终表现。
- 联网资料、相关记忆和操作回执按场景加入；不把没有发生的检索、操作或送达写成事实。

## 什么时候生效

- 文本失焦、开关点击或拖动后触发自动保存；以界面保存成功为准，而不是刚输入就生效。
- 在线保存成功后，下一次组装的提示词使用新设置，不需要重启内核。已提交给模型的请求不会被中途改写。
- 离线保存供下次启动加载；更改已保存的设置后重启应保持一致。
- 顶嘴开关归属 `config.json`；旧 `data/persona.json` 中的值仅在配置未明确设置时迁移，不能覆盖新的明确设置。
- 提示词静态化开关只决定动态资料放在 system 还是本轮消息中，不切换回旧人格。

这些是模型行为引导，不是绝对执行保证。身份认证、权限、白名单和发送限制仍由程序执行。

## 维护模块

- `src/persona/index.js`：原有调用方的兼容导出。
- `profile.js`：身份字段、输入清理与当前身份说明。
- `portable.js`：可分享字段白名单；见 [人设打包与分享](人设打包与分享.md)。
- `expression.js`：顶嘴人格、交流偏好及颜文字控制。
- `prompt.js`：静态规则、按需资料及布局构造；旧导出也使用同一套构造。
- `messageText.js`：提及识别和消息分段。
- `demo.js`：离线演示台词，不参与真实模型的提示词。
- `store.js` / `presets.js`：现有人设持久化与预设管理，保持文件与接口格式兼容。
