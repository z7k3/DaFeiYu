# 链接不回复、日记未生成与 UIA 异常核查

## 日志可确认的范围

- 第一份日志中的内核版本为 4.1.0。导出的消息判定和发送日志中仍有正常回复，没有具体失败链接及其开始/结束记录，不能仅凭此包确认是否所有会话卡住或是哪一个网址触发。
- 第二份日志中的内核版本为 4.1.6。日记开关、发送给主人开关均开启，时间为 21:00。20:59 与 21:01 之后反复记录 `no_owner_session`；同一包的聊天判定却有识别为主人的私聊。这能确认日记卡在查找主人会话阶段，没有进入模型生成或发送阶段。诊断包不含完整会话元数据，不能据此还原该用户全部记忆状态。
- 第三份日志中出现微信 4.2.0.13 UIA 控件树为空、反复激活/重建，以及 `pid must be a positive integer` 错误。导出时状态接口也未成功提供结构化状态。这些是窗口读取/绑定异常证据，不能单凭日志证明微信卡死的唯一原因。

## 本轮已做的修复

1. 链接阅读器必须在配置预算内返回，超时后取消请求，继续处理当前消息及同会话后续消息。成功或失败均有结构日志，失败事件写盘出错也不阻断聊天。
2. 外部网页解析放入可终止线程，限制并发、内存和解析时间。异常网页不能堵住内核事件循环。原有公网地址校验、DNS 绑定及重定向校验继续保留。
3. 日记读取会话时按规范微信私聊 key 兼容历史来源元数据不一致的记录；规范群聊 key 始终排除。只读使用既有聊天素材，没有修改记忆算法、会话文件或主人身份认证规则。
4. 找不到主人的私聊记录时，界面明确提示先让主人私聊并确认身份后重试；常规日志记录原因、配置是否存在和会话数量，不输出正文或内部 ID。

## 验证及边界

- 同一异常 HTML 的隔离对比：修复前超过 3 秒仍不返回；修复后返回 `parse_timeout`。
- 定向测试覆盖：永不返回的阅读器、挂起请求取消、同会话后续消息、异常网页、失败记账异常、真实存储默认元数据兼容、误标群聊排除与日记发送入队。
- 完整 Node 回归 1836 项通过；分层、发布自检和严格隐私扫描通过。
- 没有使用用户 API Key、调用付费模型、读取真实聊天正文做测试，也没有向微信发送测试消息。
- 链接与日记修复轮未修改 UIA、Win32、桥接窗口驱动或第三方运行库。
- 随后增加一项外围保护：心跳巡检连续三次失败后，保留原有的一次 UIA 重建机会，随后暂停该线程后台预热和重建；心跳上报及实际发送仍走原流程，重新连接桥接后恢复后台检查。底层 UIA/Win32/第三方库保持不变，首次 UIA 调用卡死仍需要后续独立适配及现场验证。
- “日记已加入发送队列”仍不等于微信已送达；具体用户的问题是否完全消失，需要新版实际复测。
